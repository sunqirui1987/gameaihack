# 实现规格 v1（对照编码）

本文是落地合同。行为与本文冲突时，改代码或先改本文再改代码。  
产品叙事仍看 `docs/产品说明书.md`。

版本：与 Python 包 `0.2.0` 对齐（Phase 0–5 均已接线）。

---

## 1. 包与入口

- 发行名：`gameaihack`
- 模块：`src/gameaihack`
- CLI：`python -m gameaihack` 与控制台脚本 `gameaihack` 等价
- 配置默认：`configs/pipeline.yaml`；CLI `--config` 覆盖
- 指纹规则：`configs/fingerprint_rules.yaml`（代码只读此文件，不在 py 里写死规则表）
- 雷达维：`configs/radar_dimensions.yaml`

退出码：

| 码 | 含义 |
|---|---|
| 0 | 成功（analyze 允许带警告） |
| 2 | 用法错误（路径不存在、互斥参数） |
| 3 | 输入无法打开（不是 zip/apk） |
| 4 | schema 校验失败 |
| 5 | share 消毒失败（准备打进 zip 的文件非法） |
| 10 | doctor 有缺失（非 Docker 环境允许；CI 可忽略） |

日志：人话一行阶段结论打 stderr；结构化 JSONL 写 `jobs/<id>/events.jsonl`。

## 2. CLI

```
gameaihack doctor
gameaihack inspect  <input> [--obb PATH]... [--hotupdate DIR] [--json]
gameaihack analyze  <input>
            --mode brief|standard|deep     默认 standard
            --out DIR                      默认 ./jobs
            --obb PATH                     可重复
            --hotupdate DIR
            --device NAME                  deep 才有意义；Phase 0 若带此参数则警告忽略
            --resume / --from-stage NAME
            --i-have-rights
            --thumbs-only / --full-assets
            --config PATH
            --job-id ID                    测试用
gameaihack report   <job_dir>
gameaihack share    <job_dir> --to PATH.zip
gameaihack ir-validate <game.ir.json>
```

`inspect` 默认打印人话；`--json` 打印与落盘相同结构的 stdout JSON。

无 `--i-have-rights` 且 stdin 不是 TTY 时：analyze 以退出码 2 拒绝（避免 CI 默默分析）。TTY 则问一句「确认有权分析？[y/N]」。

## 3. Job 目录（操作者）

`jobs/<job_id>/`：

```
run_manifest.json
input_profile.json
fingerprint.json
events.jsonl
pipeline.log
input/                      不复制大文件，只写 sidecar json（路径、sha256、size）
unpacked/
  container/                输入 zip 解开（xapk/apks）
  apks/<name>/              每个 apk 解开
  obb/                      obb 当 zip 解开，失败则原样放置
  hotupdate/                用户缓存拷贝或 symlink 清单
  merged/                   见 §4 合并规则
extract/raw/                Phase 0 空
extract/normalized/
ir/game.ir.json
ir/claims.json
coverage.json
report/index.html
deliverable/                与输出物规格同构
```

`job_id`：`YYYYMMDDTHHMMSSZ-<slug>-<6hex>`  
`slug` = 包名最后一段或输入文件 stem，只留 `[a-z0-9-]`，最长 24。  
`--job-id` 原样使用。

`run_manifest.json`：

```json
{
  "tool_version": "0.1.0",
  "mode": "standard",
  "started_at": "ISO-8601",
  "finished_at": null,
  "argv": [],
  "stages_ok": ["unpack", "fingerprint"],
  "warnings": []
}
```

## 4. Ingest

### 4.1 容器识别（按扩展名，再魔数）

| 输入 | 处理 |
|---|---|
| `.apk` | zip，当作单 apk |
| `.xapk` | zip；收集内部 `*.apk` `*.obb`；读可选 `manifest.json` |
| `.apks` | zip；收集内部 `*.apk` |
| `.zip` | 若内含 apk 当 xapk；否则当目录 |
| `.obb` | 仅当 `--obb` 或 xapk 内嵌 | 
| 目录 | 当作已解包 `merged/` 的输入（高级） |

不是 zip：退出码 3。

### 4.2 合并 `unpacked/merged/`

顺序 overlay（后者覆盖同路径）：

1. 名为 `base.apk` 或唯一 apk
2. 其余 split apk（名字排序）
3. obb（能当 zip 的）
4. `--hotupdate` 目录（只复制，不删除 merged 已有文件）

保留 `unpacked/apks/*` 供排错。指纹与后续 adapter **只看 merged**（可再扫 apks 补漏文件）。

### 4.3 Manifest

优先 `pyaxmlparser` 读 base apk。失败则：

- xapk `manifest.json` 的 `package_name`
- 否则 `package.name = unknown.pack`

读：`package`、`version_name`、`version_code`、`min_sdk`、主 activity、权限前 50 个。

## 5. 阶段（analyze）

| 阶段 | Phase 0 必须 | 失败策略 |
|---|---|---|
| unpack | 是 | 致命 |
| fingerprint | 是 | 致命（engine 可为 unknown） |
| extract | 空 adapter 也跑 | 警告 |
| normalize | 写出空 IR 骨架 | 警告 |
| levels | 空列表 | 跳过 |
| design | 空 claims + 雷达 | 跳过但要有雷达 |
| report | COVER/HTML/deliverable | 致命 |
| runtime | 仅 deep | Phase 0 写 warning 后跳过 |

`--from-stage` 从该阶段重跑，依赖的上游 json 必须已存在。

每阶段结束 `events.jsonl` 一条：

```json
{"ts":"...","stage":"fingerprint","ok":true,"message":"引擎 unity / il2cpp，输入分 42"}
```

`message` 必须是人话，给操作者看。

## 6. Fingerprint 输出

`fingerprint.json` 字段与 IR 内嵌副本相同，见 `ir-schema.md`。额外：

```json
{
  "matched_rules": ["unity_il2cpp", "unity_data", "addressables"],
  "protection": ["tencent_legu"],
  "shell_likely": true,
  "remote_catalog": false
}
```

引擎裁决：规则带 `engine` 的命中按 `configs/fingerprint_rules.yaml` 的 `priority` 取最高。  
`script_backend`：il2cpp 优先于 mono。  
`hotupdate`：规则 `tags` 里 `hotupdate.*` 收集去重。

## 7. 输入分 `input_profile.score`（0–100）

初始 100，扣分下限 0。

| 条件 | 扣分 | warning id |
|---|---|---|
| `shell_likely` | 40 | `likely_shell_missing_obb` |
| Unity 且 merged 无 `assets/bin/Data` | 30 | `unity_data_missing` |
| 存在 Addressables catalog 且内容含 `http` | 20 | `addressables_remote` |
| 加固 protection 非空 | 5 | `packed` |
| 输入 apk 体积 < 40MB 且 engine=unity/unreal | 15 | `tiny_package` |
| 提供了 obb 或 xapk 内含 obb | **加回** 25（不超过 100） | |
| 提供了 hotupdate 且目录非空 | **加回** 20 | |

`shell_likely` 定义：engine 为 unity 或 unreal，且看不到该引擎主资源（Unity：无 `data.unity3d` 且 Data 下无 `.assets` / `.resource` / `.resS`；Unreal：无 `.pak` / `.ucas`）。体积 < 40MB 且无 obb 只记 `tiny_package`，不单独打成壳——很多完整 2D 包就这么大。

score < 60：COVER 与 HTML 顶部必须出现残缺输入横幅。

## 8. Phase 0 GameIR

必须能通过 `ir-validate`。允许几乎全空，但：

- `package`、`fingerprint`、`input_profile`、`radar`（20 维全在）必填
- `claims` 可为 `[]`
- 雷达：`tech` 在 engine≠unknown 时 score=2；`identity` 在包名已知时 score=2；其余 0，blocker=`phase0_not_extracted`

---

## 9. 雷达打分（后续阶段，Phase 0 用固定最低分）

见 `configs/radar_dimensions.yaml`。后续公式原则：

- score 0：无信号
- 1：仅指纹/文件名
- 2：有系统存在证据（UI 名、表名）
- 3：有表或关卡可打开
- 4：表+引用+图对得上
- 5：再加模拟自洽或公式还原

任何维 `score>=3` 必须 `evidence_count>=1`（Phase 1+ 质量门；Phase 0 最高为 2）。

---

## 10. deliverable / share

`analyze` 结束时写 `deliverable/`（即使资源空）。  
`share` 把 `deliverable/` 打 zip，并跑消毒：

拒绝进入 zip（发现则退出码 5，或静默跳过并记 warning——**默认跳过并在 LEGAL 列排除清单**，若 `--strict-share` 则失败）：

- 扩展名：`apk xapk apks aab obb so dll exe dylib`
- 文件名正则：`(?i)(secret|private.?key|\.pem$|\.p12$)`

允许：json/md/html/csv/png/svg/csv/txt。

zip 根目录是游戏 slug 文件夹，不要把文件散落在 zip 根。

---

## 11. HTML（Phase 0 最低）

`deliverable/index.html` 与 `jobs/.../report/index.html` 内容相同，相对路径。

必须有：标题、一句话（Phase 0 用「尚未抽取资源，以下为体检结果」）、输入分、指纹、20 维表、warnings、未知项（空也要标题）。

纯静态、内联 CSS，不依赖外网。

## 12. 测试合同（Phase 0 必须绿）

1. 自制 zip-apk：含 `lib/arm64-v8a/libil2cpp.so` + `assets/bin/Data/data.unity3d` → inspect 得 engine=unity, backend=il2cpp

3. 假 xapk：两 apk + obb zip → ingest 合并后能看见两边文件

5. share zip 内无 `.apk` `.so`

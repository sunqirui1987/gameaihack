# 完整度矩阵

给操作者和接收者对齐期望。工程实现也按这张表认领能力，而不是按「感觉全面」。

---

## 1. 20 维 × 证据来源 × 常见失败

| 维 | 5 分长什么样 | 主要来源 | 最常见为什么不是 5 |
|---|---|---|---|
| 1 身份证 | 品类、视角、单局、付费模式都有证据 | Manifest、UI、商店文案 | 壳包，UI 还在热更里 |
| 2 表现语言 | 相机参数、分辨率、图集风格可复述 | Camera、图集、音频清单 | 3D 材质球还原差 |
| 3 操作与手感 | 按键、缓冲、郊狼、镜头阻尼、震动有清单 | Input 组件、Cinemachine、代码常量 | IL2CPP 没还原到控制器 |
| 4 玩家动词 | 动词表完整（移、打、造、抽…） | 按钮、技能表、控制器 | 手势在 native 里 |
| 5 内容库 | 主要表可开，行数可信 | SO/json/csv/lua | protobuf 无 schema |
| 6 空间与关卡 | 目录完整，代表性关能画 | Scene、tmx、棋盘 json | 关卡在服务器 / 私有二进制 |
| 7 胜负规则 | 胜、负、三星条件 | 关卡表、结算 UI | 条件在服务端校验 |
| 8 对局解析 | 公式或等效流程 | 代码 + 技能时间轴 | 只剩 dummy，无伪代码 |
| 9 成长 | 经验/装备/收集链 | 进度表 | 成长在服务器 |
| 10 经济 | 源汇图 + 货币表 | 掉落、商店、常量 | 价格服务端下发 |
| 11 商业化 | sku、广告位、抽卡概率来源清楚 | IAP、广告 SDK、gacha 表 | 概率在服务器 |
| 12 社交 | 有无好友/公会/PVP | UI、协议名 | 入口在热更 |
| 13 叙事文案 | 语言列表 + 引导/失败/商店语气 | loc | 文本加密 |
| 14 FTUE | 前 N 关机制引入顺序 | 前几关 + 引导 prefab | 新手在服务器剧本 |
| 15 界面结构 | 主界面出发跳转图 | UI prefab | 动态 UI 代码拼 |
| 16 活动运营 | 活动类型清单 | 活动表 | 活动全是运营后台 |
| 17 客户/服务端 | 哪些规则本地无效 | API、空壳关卡、error code | 没抓包（本工具默认不抓） |
| 18 Juice | 打击/受击/界面动效清单 | 粒子、Shake、Tween | 全在时间轴资源难还原 |
| 19 埋点意图 | 事件名列表 | Track/LogEvent | 混淆或自研无字符串 |
| 20 技术骨架 | 引擎、热更、分包、加固 | 指纹 | 加固导致 Java 空（通常仍可抽 assets） |

本工具 **默认不做网络抓包**。17 维能到 3 分通常就够：从客户端看出「这关本地没有地图」。要 5 分需要你们自己的抓包流程，结果可当 sidecar 喂进来（二期）。

## 2. 关卡重建等级（对外怎么说）

| 级 | 接收者能看到 | 适用 |
|---|---|---|
| L0 | 关卡表：id、名字、解锁 | 任何能发现目录的包 |
| L1 | 每关出现过哪些实体、数量 | 有预制体引用或刷怪表 |
| L2 | 能画出布局或棋盘 | Tilemap、json 棋盘、Scene 坐标 |
| L3 | 胜负、波次、触发器齐全 | 表驱动关卡（三消、塔防、Roguelike 房间） |
| L4 | 可在自研播放器里走一遍 | 产品二期，不在对外承诺里 |

标准模式对 Unity 2D / Cocos 棋盘：争取多数关 **L2**，表驱动类型争取 **L3**。  
对开放世界 / 服务端副本：诚实停在 **L0/L1**。

## 3. 引擎能力（standard 模式，静态）

分数：高 = 多数样本能到开会可用；低 = 经常只有指纹和零散文件。

| 能力 | Unity Mono | Unity IL2CPP | Cocos | Unreal | Godot | 自研 Native |
|---|---|---|---|---|---|---|
| 指纹 | 高 | 高 | 高 | 高 | 高 | 中 |
| 纹理/音频 | 高 | 高 | 高 | 中高 | 中高 | 中（看容器） |
| Prefab/场景树 | 高 | 中高（需 dummy） | 中高 | 中 | 高（tscn） | 低 |
| 字段名 | 高 | 中 | 高 | 中（需 usmap） | 高 | 低 |
| 脚本逻辑 | 高（C#） | 低 | 中（lua/js） | 低（蓝图） | 中 | 低 |
| json/csv 表 | 高 | 高 | 高 | 中 | 高 | 中 |
| 二进制表 | 中 | 中 | 中 | 中 | 中 | 低 |
| 关卡 L2 | 中高 | 中 | 中高 | 中低 | 中高 | 低 |
| 公式 | 中 | 低 | 中 | 低 | 中 | 低 |
| 付费/广告点 | 高 | 高 | 高 | 中 | 中 | 中 |

IL2CPP 的价值经常是：**dummy 字段名 + 资源 + 表**，不是「还原出可编译 C#」。对外这样讲，避免接收者以为能拿到源码。

## 4. 品类特征（决定关卡策略）

产品应在指纹之后猜品类（可错，封面标明置信度），以选择解码器优先级。

| 品类线索 | 关卡优先 | 策划优先 |
|---|---|---|
| 棋盘宽高、色块、消除 | json/bytes 棋盘 L3 | 关卡节奏、步数、道具经济 |
| Tilemap、角色移动 | Scene L2 | 手感、镜头、敌人密度 |
| SpawnWave、塔 | 波次表 L3 | 塔/敌人数值、路线 |
| 合成、点击 | 几乎无关卡空间 | 配方表、经济、广告点 |
| RPG 关卡列表 + 战斗场景 | 战斗编队 L1、地图 L0 | 成长、技能、体力 |
| Roguelike 房间预制体 | 房间模板 L2，种子关 L0 | 组合、构筑 |
| 对战/MOBA | 本地只有 UI | 商业化、英雄库；关卡声明在服务器 |

品类猜错不致命，解码器是并行尝试的；猜对能少浪费时间。

## 5. 国内安卓特有项（给别人用必做）

| 现象 | 产品行为 |
|---|---|
| XAPK/APKS | `inspect`/`analyze` 直接吃，自动合并 |
| 渠道包多包名 | 指纹里记下渠道 SDK；资源去重仍可分析 |
| UnityCN | 自动搜 key；失败列入 deep |
| 乐固/梆梆/360 | 标记加固；继续抽 assets；Java 空不报致命 |
| HybridCLR / xLua 热更 | 提示要 `--hotupdate` |
| Luban / Excel 导表 | 表发现器优先认 |
| 热更 URL | 记录，不擅自下载 |

## 7. 提高分数的合法路径（写给接收者）

雷达缺口旁只允许出现这些「下一步」：

1. 补 OBB / split / XAPK 整包
2. 补热更缓存目录
3. 换 `deep` + 设备（解密表/资源）
4. 人工标注品类或关卡格式（加解码器）
5. 你们自己抓包后把协议 JSON 丢进 sidecar（二期）
6. 人工补世界观 / 服务器规则（永远不会自动编）

没有「再跑一次 LLM 就会变 5 分」这种下一步。

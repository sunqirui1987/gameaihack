# gameaihack 在做什么

目标不是「破解出可安装的原游戏」，而是：

1. 解开 Android 游戏包  
2. 抽出能看见的美术  
3. 用 grok / Codex / DSH 读 raw/（原始）和 output/美术，写出策划到 output/策划  

成品在 `jobs/<包>/output/`：`美术/` + `策划/`。`raw/` 是原始解包，只读、不外发。

---

## 目录

```
src/gameaihack/
  cli.py                 命令入口
  doctor.py
  core/                  路径、job、进度
  ingest/                下载、解包、体检
  fingerprint/           引擎指纹
  extract/               按引擎抽资源（Unity / Cocos / 其它）
  content/               关卡索引、表、IR
  art/                   贴图抽出 → output/美术
  agent/                 grok / Codex / DSH：读 raw + 美术 → output/策划
  publish/               收口 output、分享
  pipeline/              端口 + 默认适配器 + 编排
```

流水线只认接口（`pipeline/ports.py`），实现挂在 `pipeline/adapters.py`。换抽图或换 agent，不改编排。

解包 overlay 走硬链接；抽图按容器并行（`GAMEAIHACK_ART_JOBS`，默认 CPU 上限 8），已抽出的容器按 mtime/size 跳过；`so` 字符串用正则扫、只读 il2cpp/unity 等；分享时 PNG 不再二次 deflate。每桶贴图上限 `GAMEAIHACK_ART_CAP`（默认 8000）。

```
包  →  Unpacker → Fingerprinter → Extractor
    →  LevelIndexer → ArtRipper → DesignAgent → Publisher
         raw/              output/美术     output/策划
```

---

## 能不能覆盖「一切 APK」

不能承诺一切。合理预期是：**多数商业 Unity / Cocos 的 Android 包能抽出一批美术 + 一份可读策划**；完整度和引擎、加密、热更有关。

| 层 | 对多数包 | 做不到或不稳定 |
|---|---|---|
| 解包 APK / XAPK | 可以 | 加固壳、分体缺失 |
| 认引擎 | Unity / Cocos 较稳 | Flutter、纯原生、小众引擎只有弱信号 |
| 抽图 | Unity Texture2D、包内 png | UnityCN 加密、远程 Addressables、仅热更里的图 |
| 关卡 | 能索引 ID / 章节 | IL2CPP 下几何、数值、三星条件经常解不出 |
| 逻辑 | 配置和字符串 | so / il2cpp 完整玩法代码不在范围内 |
| 策划 | grok / Codex / DSH 根据已抽出的证据写 | 证据没有的规则不能当成原作数值 |

Agent **不能**替代引擎适配器。它读的是已经解出来的文本和图。没抽出来的，模型补不出真实关卡坐标。

---

## 为什么美术和策划要分开

- **美术**是机器从引擎容器里 rip 的二进制，按资源路径归类。不同游戏目录不同。  
- **策划**是 agent 读 `raw/` + `output/美术/` 之后写的人话说明书，并把图画进图鉴。  

重做时：策划说系统怎么转，图鉴说每张图用在哪。不要把某一款游戏的主题名、角色表写死在代码里。

# 使用指南

给操作者。接收者请直接看复刻包里的 `README.md` 和 `output/复刻说明.md`。

---

## 1. 你需要准备什么

### 权利

只分析你有权分析的包。公司竞品拆解走你们自己的合规，不要把包和结果发到公开网盘。

### 材料（越齐越好）

最低：一个 `.apk` / `.xapk` / `.apks`。

更高覆盖率请尽量凑齐：

| 材料 | 什么时候需要 |
|---|---|
| 同版本 `.obb` | 主包只有几十 MB |
| XAPK 整个文件 | TapTap / 好游快爆下载的经常是这个 |
| 所有 split apk | 解压 XAPK/APKS 后不要只丢 `base.apk` |
| 热更缓存目录 | 进过游戏才有资源。模拟器：`/sdcard/Android/data/<包名>/files` |
| 已登录后的缓存 | 关卡/活动在登录后下载 |

没有后几项也可以跑，封面会写输入残缺。

### 机器

- 内存：16GB 更稳（大 Unity 包 Rip 时很吃内存）
- 磁盘：按 APK 体积预留 **10～20 倍** 空间（纹理会膨胀）
- Docker 推荐；或本机 Python 3.10+ + `gameaihack doctor` 过关

## 2. 推荐路径（Docker）

```bash
# 环境自检
docker run --rm gameaihack doctor

# 只体检，不写大文件，结果可转发给同事
docker run --rm -v $PWD:/data gameaihack inspect /data/game.xapk

# 标准分析
docker run --rm -v $PWD:/data gameaihack analyze /data/game.xapk \
  --mode standard --out /data/jobs

# 需要运行时 dump 时再加设备（深挖，可选）
docker run --rm -v $PWD:/data gameaihack analyze /data/game.apk \
  --mode deep --device emulator-5554 --hotupdate /data/cache
```

本机安装（给开发者）以仓库 README 为准；缺工具时 `doctor` 会打印缺哪一个，**不要**要求策划去编 Il2CppDumper。

---

## 3. 命令

```
gameaihack doctor
gameaihack inspect  <apk|xapk|apks> [--obb PATH]... [--hotupdate DIR] [--json]
gameaihack analyze  <输入>
            --mode brief|standard|deep
            --via sdk|grok|codex|dsh       默认 sdk（DSH Python harness）；其余为本机 CLI
            --out ./jobs
            --obb PATH                     可重复
            --hotupdate DIR
            --device emulator-5554         仅 --mode deep 时 adb pull 缓存
            --resume / --from-stage NAME
            --i-have-rights                非 TTY（CI）必须带
            --thumbs-only
            --job-id ID                    测试用
            --force-fetch                  忽略 samples/ 缓存
gameaihack report       <job_dir>
gameaihack share        <job_dir> --to ./结果.zip
gameaihack ir-validate  <game.ir.json>
```

退出码：0 成功（可带警告）；2 用法；3 打不开包；4 IR 校验失败；5 share 消毒失败；10 doctor 有缺失。

无 `--i-have-rights` 且不是交互终端时，`analyze` 会拒绝执行。

产物：

```
jobs/<包名>/
  raw/              原始解包（agent 只读）
  output/策划       生成结果：策划稿（含 关卡/第XXX章.md）
  output/美术       抽出的图音
```

Agent 两种模式：`--via sdk`（默认，[DeepSeek Harness Python SDK](https://github.com/deepseek-ai/deepseek-harness/blob/master/python/sdk/README.zh.md)，`pip install -e '.[dsh]'`）或 `--via grok|codex|dsh`（本机 CLI；有 `LLM_*` 时注入网关）。npm `dsh` 还需要 Node 22.19+/24。已有 `raw/` 则跳过解包抽取；每次重跑清空 output 策划、保留美术。

## 4. 分析前先看 inspect

`inspect` 的结论决定你还要不要去找 OBB。典型输出：

```
engine: unity 2022.3  il2cpp
protection: unitycn
input_score: 40
warnings:
  - apk=42MB, likely shell; looking for obb/splits/hotupdate
  - addressables catalog has remote URLs (not fetched)
next:
  - add OBB or play once and pass --hotupdate
```

把这段发给提供包的人，比分析完再说「怎么没关卡」高效。

---

## 5. 模式怎么选

- 立项会、只要「这是什么游戏」→ `brief`
- 给策划/程序做对照、拆系统 → `standard`（默认）
- 表是加密的、或要公式/手感、且你有模拟器 → `deep`
- 已经有 job，要发给没权限碰 APK 的人 → `share`

`deep` 只做明文资源/表 dump，不会帮你改血、去广告、过登录。

---

## 6. 跑完你该打开什么

```
jobs/<包名>/
  run.log                 全程日志（控制台同步）
  raw/                    解包，给 agent 读，不外发
  output/
    复刻说明.md           怎么用策划+美术重做
    策划/                 DSH harness 或 grok / Codex CLI 写的说明书
    美术/                 抽出的 PNG
    运行日志.txt          run.log 的副本
```

发给别人（zip 是 `output/`，不含原包）：

```bash
gameaihack share ./jobs/<包名> --to ./结果.zip
```

接收者解压后先读 `README.md` 和 `output/复刻说明.md`。

## 7. 常见失败

| 现象 | 原因 | 你能做的 |
|---|---|---|
| 资源很少 | 壳包 / 热更 / 加密 | 补 OBB、热更缓存，或 `--mode deep` |
| 关卡只有 ID 没有图 | 二进制关卡未解码，或关卡在服务器 | 看未知项；有样本格式可加解码器 |
| 字段名叫 `int_0` | IL2CPP dummy 失败 | 换 arm64 的 so；或 deep |
| 策划很空 | 没配 LLM_*，或没装 deepseek-harness-sdk | `gameaihack doctor`；`pip install -e '.[dsh]'` |
| grok 改了仓库其它文件 | job 在 git 仓库的 jobs/ 里 | 驱动会在 job 里 `git init`，把项目根钉在 job |
| 磁盘爆了 | 纹理全导出 | `--thumbs-only`，或排除 3D mesh |
| 加固后 Java 是空的 | 正常 | 游戏逻辑多半不在 Java，看 assets |

## 8. 时间与磁盘（量级，不是承诺）

| 包 | 模式 | 时间量级 | 磁盘量级 |
|---|---|---|---|
| 80MB Unity 2D | standard | 10–40 分钟 | 1–4 GB |
| 800MB 3D | standard | 1–4 小时 | 10–30 GB |
| 壳 + 热更 2GB 缓存 | standard | 看缓存 | 按缓存膨胀 |
| 任意 | brief | 数分钟起 | 远小于 standard |

可随时中断，`--resume` 接着跑。

## 9. 只给包名

```bash
# 只下载
gameaihack fetch com.unciv.app --out ./samples

# 下载并分析（F-Droid → 本机 gplaydl → Evozi 提示）
gameaihack analyze com.unciv.app --i-have-rights --out ./jobs

# 指定来源
gameaihack fetch com.whatsapp --source gplaydl
gameaihack analyze "https://play.google.com/store/apps/details?id=com.unciv.app" --i-have-rights
```

代理按这个顺序生效：`--proxy` → 环境变量 `https_proxy` / `GAMEAIHACK_PROXY` → `configs/pipeline.yaml` 里的 `fetch.proxy` → 直连。

```yaml
# configs/pipeline.yaml
fetch:
  proxy: "http://127.0.0.1:9090"   # 改成你的代理；空则直连
```

```bash
export https_proxy=http://127.0.0.1:9090
gameaihack fetch com.unciv.app
gameaihack fetch com.unciv.app --proxy http://127.0.0.1:7890
gameaihack fetch com.unciv.app --no-proxy
```

来源顺序（`--source auto`）：

1. **F-Droid** — 开源应用  
2. **APKPure CDN** — Play 上的免费应用，无需 Google 账号  
3. **gplaydl** — 需本机已 `gplaydl link`  
4. **Evozi** — 再试镜像；仍失败会给出手动下载页

只拉免费应用。付费/未授权包不要走这条路径。

## 10. 用真实游戏做一次验收（推荐 Unciv）

不要用脚本去撞 Google Play 登录墙。Play 上的商业包是版权作品，且多为 split/XAPK，没有账号和授权拿不到完整资源。

推荐用 **Play 上也有、官方同时发 APK 的开源游戏** 做端到端：

- 游戏：[Unciv](https://play.google.com/store/apps/details?id=com.unciv.app)（LibGDX 文明类，表和本地化很多）
- 下载：GitHub Releases 的 `Unciv-signed.apk`，或 `scripts/fetch_test_game.sh`

```bash
bash scripts/fetch_test_game.sh samples/unciv.apk
gameaihack inspect samples/unciv.apk
gameaihack analyze samples/unciv.apk --i-have-rights --out ./jobs
gameaihack share ./jobs/<id> --to ./unciv-autopsy.zip
```

自制黄金样本（无外网）：

```bash
python scripts/make_fixture.py samples/golden.apk
gameaihack analyze samples/golden.apk --i-have-rights --job-id golden --out ./jobs
```

## 11. 不要做的事

- 不要把 `jobs/` 整目录发到微信/网盘（里面可能有原包）
- 不要把解剖包当可商用素材库
- 不要要求工具「导出能上架的 Unity 工程」——那不是本产品
- 不要在无授权的包上跑 `deep` 去 dump

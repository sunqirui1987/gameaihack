# APK 游戏全量反编译还原 — 开发文档

> 版本：v0.3  
> 日期：2026-08-24  
> 状态：实现规格已锁定，Phase 0 落地中  
> 目标读者：工程实现、AI Agent  
> 给使用者 / 接收者：先读 `产品说明书.md` `使用指南.md` `输出物规格.md` `完整度矩阵.md`  
> **对照编码：** `docs/impl/实现规格.md` + `configs/fingerprint_rules.yaml` + `configs/radar_dimensions.yaml`

---

## 0. 一句话目标

给定一个 APK（及可选 OBB / XAPK / 分包 / 热更缓存），产出两份东西：

1. **操作者工作区 `jobs/<id>/`**：可续跑、可排错、含 raw。
2. **可交接解剖包 `deliverable/`**：别人不碰原包也能开会。结构锁死，见 `输出物规格.md`。

分析内容仍是五层：表层资源、内容库、空间关卡、规则（公式/经济/状态机）、意图（循环/FTUE/付费/手感）。  
策划不是一篇散文 GDD，而是 **20 维雷达 + `claims.json` 渲染出的章节**。无证据的主张进不了「已确认」。

## 1. 问题定义

### 1.1 真实难点（不是 unzip）

APK 只是外壳。真正的游戏内容藏在引擎私有格式、加密、热更、分包里：

| 现象 | 实际含义 |
|---|---|
| `assets/` 里几乎是空的 | 内容在 Unity `data.unity3d` / Unreal `.pak` / 自研 pack |
| 有 `libil2cpp.so` | C# 已被编译成 native，没有现成脚本可读 |
| 有 `.jsc` / `.luac` / `.bytes` | Cocos / xLua 字节码或加密脚本 |
| 有 `split_*.apk` / `.obb` | Play Asset Delivery / 扩展包，主包只是壳 |
| 进游戏后才下载资源 | Addressables / 热更 CDN，静态解包不完整 |
| 配置是 protobuf / MessagePack / 自研二进制 | 没有表头，必须靠代码或运行时 dump 还原 schema |

所以管线必须是 **静态优先 + 运行时兜底**，而不是单一工具。

### 1.2 成功标准

对一次分析任务，下面全部满足才算“完整”：

- 引擎、渲染后端、脚本后端、分包形态识别正确。
- 资源覆盖率可量化：抽出文件数 / 包内可识别资源数，缺失有原因（加密、热更、未知容器）。
- 关卡有清单：能列出全部关卡 ID，每一关至少有「类型 + 实体列表 + 胜负条件」三者之一。
- 策划文档可独立阅读：不看二进制也能理解核心循环、数值、进度、经济、关卡设计原则。
- 所有关键结论可回溯到 `file + offset/path + extractor`。
- 全程不改写原 APK、不注入作弊、不产出 exploit。

### 1.3 非目标

- 不做可重新上架的盗版工程。
- 不破解付费、不绕过服务器鉴权、不制作外挂。
- 不承诺 IL2CPP / 强混淆 native 能 100% 还原成原始 C#。
- 第一期不追求“一键导回 Unity/UE 工程可直接编译跑”。那是后续的“重建工程”产品，不是本期。

### 1.4 使用边界

只分析：自己拥有、授权分析、或法律允许逆向的样本（互操作、安全研究、已失传游戏抢救、内部竞品拆解需业务合规确认）。  
输出默认本地私有，不上传原包、不公开资源。版权素材不得二次分发。

## 2. 总体架构

### 2.1 设计原则

1. **引擎无关的中间层（GameIR）**  
   Unity / Unreal / Cocos / Godot / 自研，全部先归一到同一套 JSON。后面的关卡重建、策划合成、报告只吃 GameIR。
2. **适配器可插拔**  
   新引擎 = 新 adapter，不改主流程。
3. **证据优先**  
   任何“策划判断”必须挂 `Evidence[]`。无证据的内容标记为 `hypothesis`。
4. **静态失败才动态**  
   能从文件解出来的，不上模拟器。只有加密密钥、热更、运行时解密表，才用 Frida dump 已解密内存（只 dump 资源/表，不写 hook 作弊）。
5. **人机分工**  
   工具负责抽取与对齐；LLM 负责分类、命名、推断循环、写 GDD。LLM 不得改原始抽取结果。
6. **可复跑**  
   同一 APK + 同一工具版本 → 同一 GameIR（忽略时间戳）。配置、工具版本写入 `run_manifest.json`。
7. **可交接**  
   工作区可以脏；`share` 出去的包必须消毒、有封面、双击 HTML 能看。缺 OBB 时允许继续，但封面必须标明残缺输入。
8. **完整度是雷达不是布尔**  
   20 维 0–5 分。产品验收看雷达和抽查，不看「是否全部还原」。

### 2.2 逻辑分层

```
┌─────────────────────────────────────────────────────────┐
│  CLI / Agent 入口   gameaihack analyze ./game.apk       │
└────────────────────────────┬────────────────────────────┘
```

## 3. 端到端流水线

流水线是有向无环图，不是一条直线。某步失败不阻断后续能做的步；失败写入 `coverage.json`。

### Stage -1 — 环境与体检（给别人用的入口）

- `doctor`：依赖是否齐全；Docker 内应全绿。
- `inspect`：只做指纹 + 输入完整度，几乎不写盘。能识别壳包、XAPK 缺文件、Addressables 远程、加固。输出可转发。

`analyze` 在 Stage 0 之前必须跑一遍与 `inspect` 相同的体检，写入 `input_profile.json`。

### Stage 0 — 任务登记

输入：

```yaml
apk: ./samples/foo.apk          # 必填
obb: []                         # 可选
splits: []                      # 可选 XAPK / APKS
hotupdate_dir: null             # 可选已下载热更缓存
out: ./jobs
device: null                    # 可选：adb 设备，用于运行时 dump
```

动作：计算 SHA256、包名、版本号、文件大小；创建 job 目录。

### Stage 1 — 解包

顺序：

1. 识别容器：`.apk` / `.xapk` / `.apks` / `.zip`。
2. `unzip` 抽文件树；`apktool d -s` 解码 `AndroidManifest.xml` 与 `res/`（`-s` 跳过 smali，加快；需要 Java 逻辑时再全量）。
3. 合并 split APK（`base` + `unity` + `asset` + ABI）。
4. 若存在 `*.obb` / `main.*.obb`，当 zip 或 raw 一并挂入 `unpacked/obb/`。
5. 扫描 `AndroidManifest`：`package`、权限、activity、meta-data（常有引擎版本、渠道、热更 URL）。

输出：`unpacked/` + `manifest_summary.json`。

### Stage 2 — 指纹（最关键的路由步）

用规则引擎打标签，不要一上来就跑重工具。

**文件级信号**

| 信号 | 判定 |
|---|---|
| `assets/bin/Data/data.unity3d` 或 `global-metadata.dat` | Unity |
| `lib/*/libil2cpp.so` | Unity IL2CPP |
| `assets/bin/Data/Managed/Assembly-CSharp.dll` | Unity Mono |
| `lib/*/libUE4.so` / `libUnreal.so` + `*.pak` | Unreal |
| `lib/*/libcocos2djs.so` / `libcocos2dlua.so` + `.jsc/.luac` | Cocos |
| `lib/*/libgodot_android.so` | Godot |
| `lib/*/libflutter.so` | Flutter（少见做重游戏） |
| `assets/index.android.bundle` | RN |
| `lib/*/libmain.so` + 自研 pack 头 | Native / 自研 |
| `lib/*/libexec.so` 且 dex 被抽空 | 加固（乐固/邦邦/爱加密/360） |
| `assets/aa/` 或 `catalog.json` | Unity Addressables |
| `HybridCLR` / `hotupdate.dll.bytes` | HybridCLR 热更 |
| `Lua` + `xlua.so` | xLua |

**加固处理**：指纹到加固后，Stage 1.5 走脱壳（仅当用户明确授权、且有设备）。无设备则标记 `packed=true`，后续只分析未加固部分（assets 往往仍可读）。

输出：`fingerprint.json`，示例见 `docs/ir-schema.md`。

### Stage 3 — Adapter 抽取

按指纹并行调用 1~N 个 adapter。每个 adapter 必须实现同一接口：

```
extract(unpacked_dir, out_dir, fingerprint) -> ExtractReport
```

`ExtractReport` 包含：成功文件列表、失败列表、警告、覆盖率估计。

### Stage 4 — 规范化到 GameIR

把引擎私有结构翻译成第 5 章的 IR：

- 纹理 → `Resource{kind:texture, path, width, height, format, refs}`
- 音频 → `kind:audio` + duration/codec
- 预制体/蓝图 → `EntityTemplate`
- ScriptableObject / DataTable / csv / json / protobuf → `Table`
- Scene / Level / Tiled / 自研关卡二进制 → `LevelStub`（尚未重建，仅索引）
- Localization string table → `LocBundle`

这一步做 **去重**（同一贴图在 atlas 与 raw 各一份）、**引用图**（谁用了谁）、**命名修复**（hash 文件名用引用反查）。

### Stage 5 — 关卡重建

见第 7 章。产出 `ir/levels/<id>.json` + 可选 2D 俯视 PNG。

### Stage 6 — 策划合成

见第 8 章。产出 `design/*.md`。只读 IR，禁止回写 raw。

### Stage 6.5 — 图与模拟（standard 能跑就跑）

从 IR 生成：循环图、经济源汇图、关卡进度图、UI 跳转、FTUE 时间线。失败出空图 + blocker。

有足够表时跑最小模拟（战斗清关时间、F2P 7 日经济、解锁可达性）。离谱则降低对应维分数，不删数据。

### Stage 7 — 报告、雷达、解剖包

`coverage.json` 必须回答：

- 资源：抽出 / 识别到 / 加密未解 / 热更缺失
- 代码：Java / C# dummy / IL2CPP 伪代码 / Lua 源 / 失败
- 关卡：已重建 / 仅索引 / 未知格式
- 表：已解码 / 仅二进制 / schema 未知
- 策划章节：高/中/低置信度占比

HTML 报告做资源墙、关卡缩略图、表浏览器、GDD 导航。

### Stage 8 — 运行时兜底（可选）

触发条件（任一）：

- 资源明显加密（熵高、无已知头）
- 主包几乎无关卡，但 Manifest 有热更 URL
- 配置表 protobuf 无 `.proto`
- XXTEA / AES 密钥静态找不到

动作（需用户提供设备或模拟器）：

1. 安装原包（不重打包、不 hook 支付）。
2. Frida 仅 hook 解密函数/文件读取，把 **解密后的明文** 写到 `extract/runtime/`。
3. 把 dump 结果重新送入 Stage 3。

禁止：改数值、秒杀、解锁付费、中间人改服务器回包。

## 4. 引擎适配器设计

每个 adapter 分四路：**资源、代码、配置、关卡**。下面按移动游戏占比排序。

### 4.1 Unity（第一期必须打穿）

移动 APK 里占比最高，也最有成熟工具。

**资源**

| 输入 | 工具 | 输出 |
|---|---|---|
| `data.unity3d` / `*.assets` / `*.bundle` / Addressables | AssetRipper CLI 或 UnityPy | 纹理/网格/动画/音频/材质/Prefab/Scene |
| UnityCN 加密 bundle | UnityPy + 密钥（从 so 或 meta 搜） | 解密后再 Rip |
| SpriteAtlas | 拆图 + 保留图集映射 | `sprites/` + `atlas.json` |

策略：

- 优先 AssetRipper（能出接近工程的 YAML Scene/Prefab）。
- AssetRipper 失败则 UnityPy 按类型导出（Texture2D、AudioClip、TextAsset、MonoBehaviour）。
- TextAsset 一律当配置候选：json/xml/csv/bytes/lua。

**代码**

```
Mono:    Managed/*.dll  → ILSpy / dnlib  → C# 源
IL2CPP:  libil2cpp.so + global-metadata.dat
         → Il2CppDumper / Cpp2IL
         → dummy dll（给 AssetRipper 还原 MonoBehaviour 字段名）
         → 可选 Ghidra 伪代码（只对关键类：关卡加载、数值、经济）
```

要点：dummy dll 不是“玩的”，是 **还原字段名的关键**。没有它，Scene 里全是 `MonoBehaviour PPtr` 不知道是 Enemy 还是 Coin。

热更：

- HybridCLR / ILRuntime：热更 dll 在 `assets` 或缓存目录，当 Mono 处理。
- xLua / toLua / Puerts：脚本当 Lua/JS 处理，和 Unity 资源并行。

**配置（策划的金矿）**

优先级：

1. `ScriptableObject`（EnemyData、LevelConfig、ItemTable）
2. `TextAsset` 的 json/csv/xml/xlsx（Luban / EasySave / 自研）
3. protobuf / MessagePack / FlatBuffer（用 dummy 类或运行时 dump schema）
4. 代码里的 `const` / `static readonly` 数值

**关卡**

- `*.unity` Scene YAML：Transform 树 + 组件
- Tilemap / Grid / RuleTile
- 自研 `Level_001.bytes`（常见于消除、塔防、合成）
- Addressables 标签 `level` / `stage` / `map`

分类器（规则 + LLM）：

- `tilemap_2d`：有 Tilemap/Grid
- `scene_graph_3d`：大量 MeshRenderer
- `wave_spawner`：有 SpawnWave / 时间轴
- `puzzle_board`：宽高网格 + 元素枚举
- `runner_segment`：片段预制体拼接
- `ui_only`：菜单场景，不当关卡

### 4.2 Cocos（2d-x / Creator）

**资源**：`res/`、`.plist` + `.pvr.ccz` / `.png`、图集、Tiled `.tmx`、`.anim`。  
**脚本**：

- Lua：`.lua` 明文 / `.luac` / LuaJIT；常 XXTEA。密钥从 `libcocos2dlua.so` 静态搜或 Frida 第 3 参 dump。
- JS：`.js` / `.jsc`（同样 XXTEA）。Creator 还有 `config.json`、uuid 资源库。

**关卡**：Tiled 地图、Creator Prefab、json 关卡（消除/三消几乎全是 json 棋盘）。

密钥提取只做静态字符串扫描 + 解密函数参数回溯，不写通用 exploit。

### 4.3 Unreal

- `*.pak` / `*.ucas+utoc` → CUE4Parse / FModel CLI 导出。
- Android 上 `libUE4.so` + `main.obb*.pak`。
- 关卡是 `umap` + `uasset` DataTable。
- 蓝图不能完美还原为可编译 Blueprint，只能导出节点属性 JSON。对策划来说 DataTable + 关卡 actor 列表通常够用。

### 4.4 Godot

- `pck` / embedded；Godot 4 资源可部分还原。
- `.gd` 若被编译为 bytecode，用官方反编译器或 gdc 工具。
- 场景是 `.tscn` 文本时最友好，几乎不用猜。

### 4.5 Native / 自研引擎

路径：

1. jadx 解 Java/Kotlin（SDK、支付、热更入口）。
2. `res/raw`、`assets/` 扫文件头（png/ogg/zip/json）。
3. 自研 pack：看 magic（`PK`、`NPk`、`ABFS`…），写专用 unpacker。
4. `libmain.so` 用 Ghidra 只分析 `loadLevel` / `readConfig` 一类符号。
5. 第一期：识别 + 抽出能认的文件；未知容器记入 unknowns，不阻塞。

### 4.6 加固与保护

| 保护 | 处理 |
|---|---|
| 腾讯乐固 / 梆梆 / 360 | 标记 packed；assets 仍抽；代码等用户授权脱壳 |
| UnityCN | 专用解密 |
| AssetBundle AES | 从 so / 配置搜 16/32 字节 key |
| XXTEA + sign header | 扫 so 字符串；失败再运行时 dump |
| 资源无扩展名 hash | 靠引用图回填名字 |
| 服务器权威关卡 | 只能还原客户端缓存；GDD 标注“关卡在服务端” |

## 5. 资源还原规格

### 5.1 要抽出的类型

必须覆盖：

- 纹理、Sprite、图集、九宫、字体、Spine/DragonBones/Live2D
- 网格、材质、Shader、动画 Clip、Animator Controller
- 音频（BGM/SFX 分离）、视频
- UI Prefab / 图集 / 字体 fallback
- 特效（粒子、Prefab）
- 配置与本地化
- 视频/Live2D 等大文件只索引不强制转码

### 5.2 资源目录规范

```
extract/normalized/resources/
├── textures/
├── sprites/
├── atlases/
├── models/
├── animations/
├── audio/bgm|sfx|voice
├── ui/
├── vfx/
├── fonts/
├── shaders/
├── video/
└── misc/
```

每个资源一条 sidecar：

```json
{
  "id": "res_tex_000123",
  "kind": "texture",
  "original_path": "assets/bin/Data/sharedassets0.assets",
  "export_path": "textures/enemy_slime.png",
  "sha256": "...",
  "meta": {"w": 256, "h": 256, "format": "RGBA32"},
  "referenced_by": ["entity:enemy_slime", "level:stage_01"]
}
```

### 5.3 覆盖率怎么算

```
resource_coverage = exported_unique_hashes / discovered_unique_hashes
```

`discovered` = 容器目录 + 清单 + bundle 索引。加密未解、热更未下、工具不支持，分母保留、分子不计，原因写入 coverage。

## 6. 配置表与数值还原

策划还原的质量，80% 取决于表。

### 6.1 发现器

扫描：

- 文件名含 `config|table|data|level|stage|enemy|item|shop|drop|buff|skill`
- 扩展：`json csv xml xlsx bytes bin lua pb dat`
- Unity MonoBehaviour 中字段全是 int/float/string 数组的
- 重复结构的二进制（Luban 导出常见）

### 6.2 Schema 推断

1. JSON/CSV：直接成表。
2. ScriptableObject：用 dummy dll 字段名。
3. Protobuf：若有 `.proto` 或 C# 生成类则用；否则 `protoc --decode_raw` + LLM 猜列语义，标 `schema_inferred`。
4. 纯二进制：启发式（int32 网格宽高、float 血量范围），进 unknowns。

### 6.3 语义打标（LLM + 规则）

给每张表打角色：

`item` `enemy` `skill` `buff` `level` `drop` `shop` `iap` `dialogue` `quest` `spawn_wave` `economy_const`

打标依据：列名、样例值、被谁引用。禁止只凭文件名。

## 7. 关卡还原

### 7.1 目标形态

不管原引擎是 Scene 还是 json 棋盘，统一成：

```json
{
  "id": "stage_001",
  "name": "森林入口",
  "kind": "tilemap_2d",
  "size": {"w": 32, "h": 18, "unit": "tile"},
  "win": [{"type": "reach_exit"}],
  "lose": [{"type": "player_hp <= 0"}],
  "layers": [{"name": "ground", "tiles": []}],
  "entities": [
    {"template": "player_spawn", "x": 2, "y": 3},
    {"template": "slime", "x": 10, "y": 8, "props": {"hp": 30}}
  ],
  "triggers": [],
  "waves": [],
  "evidence": [{"path": "Assets/Scenes/Stage001.unity", "extractor": "unity.scene"}]
}
```

完整字段见 `docs/ir-schema.md`。

### 7.2 重建算法

1. **发现关卡入口**  
   代码符号 `LoadScene` / `LoadLevel` / `StageManager` / Addressables key；表中 `stageId`；文件名模式 `level_\\d+`。
2. **列出关卡目录**  
   得到 `LevelIndex[]`：id、源、是否解锁依赖。
3. **按 kind 走解码器**
   - Unity YAML Scene → 场景图
   - Tilemap → 稀疏二维数组
   - JSON 棋盘 → 直接映射
   - 二进制 → 先找宽高与 palette，再网格
   - Unreal umap → actor 列表
4. **实体对齐**  
   Prefab/模板 id 对上 `EntityTemplate`（血量、碰撞、掉落）。对不上则 `template: unknown:<hash>`。
5. **规则抽取**  
   从代码/表抽 win/lose、限时、三星条件、波次。
6. **可视化**  
   2D：画 tile + 实体图标。3D：导出 glTF 缩略或俯视投影。失败则只出实体表。
7. **关卡设计特征**  
   供策划章使用：平均长度、敌人密度、引入新机制的关卡号、难度曲线（建议用敌人 hp 总和 / 玩家 dps）。

### 7.3 关卡还原的及格线

| 等级 | 标准 |
|---|---|
| L0 索引 | 只知道有 N 关和 id |
| L1 清单 | 每关有实体类型计数 |
| L2 布局 | 有坐标可画图 |
| L3 可玩语义 | 有胜负、波次、触发 |
| L4 可重玩 | 导出到自研播放器（二期） |

第一期目标：**主流 Unity 2D/轻度 3D 达到 L2，有表的三消/塔防达到 L3**。

## 8. 策划文档合成（核心差异化）

工具抽出的是“有什么”；策划要回答“为什么这样设计”。这一步必须 **LLM + 证据**，禁止凭空写设定。

### 8.1 输入包（给模型的唯一上下文）

- `fingerprint.json`
- 资源统计（不喂全部图片，只喂清单 + 少量代表图 caption）
- 全部表的 schema + 前 20 行 + 行数
- 关卡索引 + 3~5 个典型关（首关、中期、Boss、教学关）
- UI 树（主界面、商店、战斗 HUD）
- 代码里抽到的状态机/枚举名（`GameState`, `ItemType`）
- 本地化 key 抽样（商店、引导、失败文案）

上下文要可控：大表只给统计和极值，不把 2000 个物品全文塞进提示词。

### 8.2 先 claims，再渲染章节

禁止模型直接写终稿 Markdown。

```
GameIR → 规则探测器 + LLM 打标 → claims.json → 渲染 design/*.md 与 COVER.md
```

20 维清单以 `产品说明书.md` 第 5 章为准。每条 claim 含 `dimension/confidence/evidence`。  
章节只是 claims 的分组渲染，另附三张主图：局内循环、经济源汇、关卡进度。

### 8.3 推断规则（写进合成器，不靠模型自觉）

- 发现 `RewardedAd` / `ShowRewardVideo` → 广告点，记录触发界面。
- 发现 `IAP` / `SkuDetails` / `ProductId` → 付费点。
- 体力字段 `stamina/energy` + 时间回复 → 体力系统。
- `gacha/recruit/wish` + 概率表 → 抽卡；概率以表为准。
- 关卡 `pre_id` / `unlock_star` → 进度门。
- 商店价格随关卡递增 → 通胀假设，标 hypothesis。
- **禁止**：编世界观 Lore、编未出现的职业、编数值公式。

### 8.4 人审点

自动生成后必须能打开 `unknowns.md`。人工只补三类：世界观、公式、服务端规则。补完可再跑一版 GDD，不重抽资源。

- 未知项是否诚实

## 12. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| IL2CPP 无符号、metadata 加密 | 字段名全丢，关卡变成无意义坐标 | dummy 失败则用运行时 dump 对象；GDD 降级为资源+表 |
| 关卡在服务器 | 客户端只有空壳 | 明确写“服务端关卡”；只还原缓存与回放 |
| Addressables 远程 | 主包覆盖率低 | 记录 catalog URL（不擅自打服务器）；支持用户导入已下载缓存 |
| 超大包 4GB+ | Rip 极慢 | 按类型增量；先 TextAsset/Scene 后纹理 |
| LLM 幻觉 Lore | 策划文档不可信 | 证据强制；禁用无表世界观 |
| 法律风险 | 侵权分发 | 默认本地；CI 只用自制包 |
| 加固 | Java 层不可读 | 游戏逻辑通常不在 Java；继续抽 assets |

## 16. 产品化工程要求（v0.2 增补）

实现时把这些当硬需求，不要留到「最后做个 UI」。

1. **输入**：apk / xapk / apks / 多 split / obb / `--hotupdate` 目录，同一套 Ingest。
2. **人话日志**：每阶段结束一行中文结论，禁止只打 traceback。
3. **可 resume**：大包默认假设会中断。
4. **brief 可提前出封面**：资源导出是后台增量，制作人不等 3D mesh。
5. **资源命名**：hash 名必须走引用图回填；LLM 只建议 `display_name`，保留 original_path。
6. **share 消毒单测**：zip 内出现 `.apk` 或 `libil2cpp.so` 或疑似 key 文件 → 测试失败。
7. **HTML 无后端**：相对路径；附 `OPEN.txt`。
8. **CSV 带 UTF-8 BOM 可选**：Excel 打开中文。
9. **Docker 是默认分发**；本机路径允许缺工具降级（brief 仍能 inspect）。
10. **品类启发式**只影响解码器顺序，不删数据。

## 17. 手感、埋点、公式（L4/L5 的硬抽）

这些不是「有空再写进 GDD」，要进 IR。

**手感 inventory**（`feel.inventory`）扫描：

- Input：axis、buffer、coyote、jump cut、惯性
- Camera：size、damping、deadzone、shake 振幅/时长
- Juice：hit stop、flash、knockback、粒子 Prefab 名、震动 API
- UI Tween：按钮 scale、弹窗曲线

找不到就空清单，雷达第 3、18 维打低分。

**埋点**（`analytics_events`）：字符串扫描 `Track`/`LogEvent`/`Report`/`firebase`/`thinkingdata`/`appsflyer`。事件名本身就是设计意图。

**公式**：只从代码符号/lua/明文脚本还原。IL2CPP 无伪代码时写 `formula_unknown`，模拟器用表里的裸 ATK/HP 当弱替代并标明。

**客户端/服务器**：关卡目录为空但有 `stageId` 请求；商店价格表为空但有 `GetPrice` RPC；抽卡只有结果展示没有权重表 → 第 17 维给「服务端权威」结论，这是高价值结论，不是失败。
